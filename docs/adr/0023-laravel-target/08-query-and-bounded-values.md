### Query and bounded values

- **Query.** Decoded from the raw `QUERY_STRING` by the IR's wire form, with form decoding (`+` is a space), never from `$request->query`, since PHP's `parse_str` turns `.` and spaces in a name into `_` and reads `a[]` as an array. Zero body bytes is no body. The media type is matched exactly.
- **Body limit.** The boundary refuses a declared `Content-Length` above the route's limit before reading. It reads the request's content stream in chunks through `getContent(true)` (`php://input`, or the content an in-process request carries, as `postJson()` in a feature test sends), decodes `gzip` and `deflate` with ext-zlib's `inflate_add`, counts both the encoded and the decoded bytes, and answers the route's 413 as soon as either passes the limit, chunked bodies included (spike, CLI server).
  - Any other content coding answers 415; a corrupt compressed body is the client's 400.
  - The app's `getContent()` keeps the bytes as received. The boundary's input, and a signed route's raw body, are the decoded bytes.
  - The web server's limit and `post_max_size` must be at least the largest route limit; the Laravel guide says so. The target exports no limit constant.
- **Paging.** The paging roles, `overLimit` included, are validated in step 6, before any paginator is built, since Laravel's page resolver falls back to page 1 on a bad value. `LengthAwarePaginator` and `CursorPaginator` appear only for the `laravelPages` and `laravelCursor` styles of the `pack:laravel` profile (ADR 0008), never as a default shape. Under those styles the handler answers Laravel's paginator (the `LengthAwarePaginator` or `CursorPaginator` contract), from which the boundary reads the items and the total or the encoded cursors and renders the pack's `{ data, links, meta }`; the page and the limit it renders are the request's, never the paginator's own. Its links are the contract's references, a query-only `?page=2` under relative URLs and the public origin's URL under absolute ones, never the paginator's URLs built from the request host, and `meta.path` is the request path. An item, table or list body is written in its format's envelope (`{ data: $payload }` under `pack:laravel`), as on the Node targets; a format meta member, a success header or an envelope slot other than the payload, the status and the path is refused by name until a contract needs one.
- **Deadlines and relays.** A deadline header is a declared header the boundary validates and hands to the handler, which stops the work and throws the operation's `deadlineExceeded` error once it has passed, as on the Node and Spring targets; `budgetMs` is the client's timeout and changes nothing in the boundary. A relay route (`relays`) is an operation of its own api, generated and served as any other, with the shape it copies and no field rights. A `degradable` operation is refused by name until after 1.0, as on Spring.
- **Several apis.** Each api's provider registers its boundary and its base paths under the container key `seampact.boundaries`, so each boundary check accepts the other apis' boundaries before it, unless one claims this api's paths with its `catch_all` on. A 400 lists its issues by part: path, query, header, body.
- **Keys.** The throttle bucket key and the idempotency key are fixed-size SHA-256 digests with the same bytes, hex and base64url text as the Node and Spring targets, so keys and ETags are equal across targets. The idempotency key is derived as ADR 0012 obligations say, never from the credentials. Of a principal the boundary reads only the members its identity's principal schema declares, through the generated `<Identity>PrincipalMembers` interface, one accessor per member, which the generated `<Identity>Principal` class implements; a hook that returns another object answers the api's 500 with a log line naming the class and the fix. Symfony's `ResponseHeaderBag` writes `Cache-Control` in its own order (`max-age=60, private`) and adds `no-cache, private` where the contract writes none; the directives are the same as on the other targets.
- **Version tokens.** The boundary validates the expected version with the body; the handler compares it with the stored version and answers the operation's `stateConflict` error, as on the other targets. The Laravel guide says what the Node targets' "left to the handler" warnings say.
- **Absolute URLs.** Under `api.wire.urls: absolute`, every URL starts with the configured public origin, `config('seampact.<api>.public_origin')`. Under relative URLs, the boot check fails when it is set. It also fails without it under absolute URLs, or on a value Java's `URI` would refuse as a scheme, a host and a port (a host that is not a DNS name, an IPv4 or a bracketed IPv6 address, a port outside 1-65535), as the Spring target checks it. The request host and forwarded headers are never read. Trusted proxies stay the app's own `trustProxies()` setting; they change Laravel's URL helpers, never the boundary.
