# seampact 1.0.0

seampact 1.0.0 is the first release. You write one contract in YAML. seampact generates the server boundary, the client and the OpenAPI document from it, and checks in CI that nothing drifted.

Every package, in every ecosystem, has the same version. [Install](../getting-started/01-install.md) shows how to get each one.

## Where to get it

| Registry | What you get | Status |
|---|---|---|
| npm | the CLI, the generators, the runtime and the packs | live, 2026-11-07 |
| Maven Central | the Spring Boot runtime, the hooks, the Maven plugin and the compiler | live, 2026-11-07 |
| Gradle Plugin Portal | the Gradle plugin `io.github.jubasse.seampact` | pending review, 2026-11-07 |
| Packagist | `seampact/laravel`, `seampact/symfony` and their libraries | live, 2026-11-07 |
| PyPI | `seampact-fastapi`, `seampact-drf`, `seampact-ninja` and their libraries | live, 2026-11-07 |
| GitHub releases | the compiler binary for five systems, with `SHA256SUMS` | live, 2026-11-07 |

The Gradle Plugin Portal reviews each new plugin by hand, which takes a few days. Until it approves, the Maven plugin works at once, and Gradle builds can load the plugin from Maven Central: see the [Spring Boot guide](../backend/spring-boot.md).

On release day, pnpm can answer "no matching version" for `@seampact/*`. Its `minimumReleaseAge` setting holds back a package published in the last day. Wait, or add `minimumReleaseAgeExclude: ["@seampact/*"]` to `pnpm-workspace.yaml`: see [Install](../getting-started/01-install.md).

## What 1.0 ships

Servers:

- Node.js: [NestJS](../backend/nestjs.md), [Express](../backend/express.md), [Fastify](../backend/fastify.md), [AdonisJS](../backend/adonisjs.md) and [Hono](../backend/hono.md).
- Java: [Spring Boot](../backend/spring-boot.md), with a Gradle plugin and a Maven plugin.
- PHP: [Laravel](../backend/laravel.md) and [Symfony](../backend/symfony.md), with Composer.
- Python: [FastAPI](../backend/fastapi.md), [Django REST Framework](../backend/drf.md) and [Django Ninja](../backend/ninja.md).

Clients and validators:

- A typed `fetch` client, React hooks (TanStack Query, SWR or RTK Query) and TypeScript types.
- Validators with zod, yup or class-validator.

Everything else:

- The OpenAPI 3.1 document of each api.
- `seampact diff` classifies a change as additive or breaking, and `seampact check` fails CI on drift.
- Access rights, signed webhooks, idempotency keys, paging and conditional requests.
- The standalone compiler binary: `compile`, `lint`, `diff`, `explain` and `bundle` without Node.js.

## Known limits

A form that 1.0 does not support is refused by name when you run `seampact generate`. The message says which form and where. Nothing is generated silently wrong. [Generate errors](../troubleshooting/generate.md) explains most of them. Where a line says "remove the operation", list the other operations in the entry's `operations` filter and write that one by hand.

Every server (the Node servers, Spring Boot, Laravel, Symfony, FastAPI, DRF and Ninja):

- A principal with variants (`viewer_or_device`), a principal requirement and a principal binding are refused. Declare one principal kind per route and check the principal in your handler.
- A signature scheme that your application verifies is refused. Verify the signature in your own middleware and leave it out of the contract.
- An API key in the query string and HTTP Basic are refused. Send the key in a header, or use a bearer token.
- A scope that your application resolves (`resolver`) is refused. Declare the scope from the path (`path.projectId`) or the subdomain.
- An identity header written on a response (also by the `fetch` client), such as the rights-version header (`identity.response.header.unsupported`), is refused. Remove it from the identity's `headers`, or declare a deadline, trace or actor header `in: request`.
- `accessHooks: false` (native access) is refused. Keep the hooks and read the framework's own auth in the authenticate hook.
- A sort key restricted by a right (`sortable: [{ key, right }]`, or a key of a field with `restrictedTo`) is refused. Leave the key out of `sortable`.
- A page or an item that writes the `$collection`, `$resource` or item id slots (JSON:API, HAL, JSON-LD) is refused. Use a page style without them.

Every server and the `fetch` client:

- Form, multipart and file download bodies are refused. Remove the operation.
- A redirect response is refused. Remove the operation.
- A response header that the route writes itself is refused. Remove the operation.
- A tagged union (`oneOf` with a discriminator) is refused, and by zod too. Remove the operation.
- A degradable operation is refused. Remove the operation.
- A query list in brackets form (`tag[]=a`) is refused. Set `conventions.query.lists` to `repeat` or `comma`.
- A deprecated operation is refused by the `fetch` client only. Remove the operation from the client entry.

Node servers:

- Optional authentication is refused. Spring Boot, Laravel, Symfony, FastAPI, DRF and Ninja generate it.
- Absolute URLs in responses are refused. Use relative URLs; Spring Boot, Laravel, Symfony, FastAPI, DRF and Ninja write absolute ones from a configured public origin.
- The `split` sort style is refused. Use `signed`, `pair` or `keyed`.
- An input field right below the top level of the input (`/details/budget`) is refused. Put the field at the top level of the input, or check the right in your handler.
- `idempotency.enforce: none` is refused. Keep `boundary`. Spring Boot, Laravel, Symfony, FastAPI, DRF and Ninja generate it, but the 1.0 test suite does not cover it there yet.

PHP and Python servers (Laravel, Symfony, FastAPI, DRF, Ninja):

- The complete page fact of a changes-since paging style is refused. Use another paging style on these servers.

Spring Boot, Laravel and NestJS:

- The `suffixes` option and per-operation handlers (`perOperation`) are refused. Use the default names and the default `perResource` handlers.
- A custom metadata on a right is refused on NestJS and Laravel. Leave it out of the right.
- The `codeName` option is refused on NestJS. Spring Boot and Laravel support it.

Clients and validators:

- An open enum with a fallback is refused in the types the `fetch` client is generated beside. Declare a closed enum.
- An error format that writes its code only inside a text template is refused for the `fetch` client. Put the code in a field of its own.
- The `ignore` and `keep` policies for unknown keys of an operation input are refused with the zod, yup and class-validator validators. Keep the default, which refuses unknown keys.

Known differences between servers. A portable client avoids them:

- A `comma` list sent as an empty value (`sort=`) is an empty list on the Node servers and one empty item on Spring Boot and PHP.
- A `comma` key sent twice (`sort=a&sort=-b`) answers 400 on the Node servers. Spring Boot and PHP join both values.
- `limit=1e3` is read as 1000 on Node. Spring Boot, Laravel, Symfony and FastAPI answer 400.

Not in 1.0:

- API Platform comes after 1.0. Use Symfony with its own controllers, as the [Symfony guide](../backend/symfony.md) shows.
- The CASL (NestJS) and spatie (Laravel) adapters come in 1.1. Until then, write the rights in your own guard or policy.
- Test helpers, dev docs served by the server, and a ready-made idempotency store are not generated on the Node, Java, PHP and Python servers. The idempotency store is an interface you implement; the Node servers have an in-memory one.
- Express, Fastify, Hono and FastAPI generate no native access export, and Express, Fastify and Hono map no framework security refusals: your own middleware owns them.
- The Angular service does not set HttpClient's XSRF header. Call `withXsrfConfiguration` with the contract's CSRF header name, as the [Angular guide](../frontend/angular.md) says.
- The `fetch` client does not retry by the nature of an error code. It retries a rejected request, never a declared error.
- The binary and the plugins download over HTTPS only and read no proxy variable. Behind a proxy, put the binary on a mirror and set its URL and hash, or point to a local file.
- macOS binaries carry an ad hoc signature, not an Apple one. If macOS blocks the file, allow it in System Settings.
