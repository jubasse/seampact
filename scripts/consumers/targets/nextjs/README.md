The Next.js 16 consumer: one catch-all route file per base path of the reference apis, built with `next build --webpack` and served by `next start` on the Node.js runtime, running the http suite's default profile (the hand-written and boot profiles wait). Route files are `route.tsx`, and the config `next.config.mts`, so the monorepo's `scripts/**/*.ts` typecheck leaves them to the consumer; the shared sample sources are `.mts` with `.mjs` specifiers, which Turbopack does not resolve, hence webpack here. Two default-profile cases are refused by name (`test/target-suite-refusals.mts`): `not-found-doubled-slash`, since Next answers a `//` path with its own 308, and `mount-mismatch-refused-at-first-request`, since this consumer starts no boot variant app. `turbopack-app/` holds the generated tree alone, and `test/turbopack-build.test.mts` builds it with Turbopack, Next.js 16's default bundler.
