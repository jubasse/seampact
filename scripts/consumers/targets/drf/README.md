The DRF consumer (ADR 0027 "The consumer and the proof"): a Django project that `seampact-drf` generates the reference contract's tasks api into, serving every operation of the `tasks` and `tasksService` apis, its handlers, hook doubles and control views, and the suite run that checks it with the shared http suite under gunicorn (WSGI) or uvicorn (ASGI).

- `../../php/bundle.sh <binary> <out>` bundles the reference contract with the compiler binary into `<out>/bundle` and writes its integrity pin to `<out>/integrity`; it is the one step that needs the binary.
- `assemble.sh <work> <out> [allow-listed]` assembles the app as the shared `../../python/assemble.sh` does: `<work>/app`, or `<work>/app-allow-listed` built from `seampact.allow-listed.config.yaml` for the `allow-listed-framework-route` boot variant.
- The install (`../../python/README.md`): `requirements.sh <file> seampact-drf generate <gunicorn or uvicorn>` and `uv build --all-packages --wheel` in `python/`, then `install.sh <venv> <file> <wheels> 'seampact-drf[generate]' [python/drf/ci/django-floor.txt]`; in an assembled app, `<venv>/bin/seampact generate`.
- `app/settings.py` lists the generated `TasksBoundary` first in `MIDDLEWARE` and names in `SEAMPACT` the handler factories of `app/handlers.py` and the hook doubles and idempotency store of `app/hooks.py` (the framework-free ones come from the shared `seampact_consumer_suite`), less the binding `SEAMPACT_SUITE_BOOT_VARIANT` names; `app/urls.py` includes the api's patterns beside the control views; `app/wsgi.py` and `app/asgi.py` are the served apps.
- From the repository root, with `SEAMPACT_DRF_SERVER` (`gunicorn` or `uvicorn`), `SEAMPACT_DRF_APP`, `SEAMPACT_DRF_ALLOW_LISTED_APP`, `SEAMPACT_DRF_VENV` and `SEAMPACT_DRF_REPORTS` set: `pnpm vitest run --config scripts/consumers/targets/drf/suite/vitest.config.ts` runs the `default`, `hand-written` and `boot` profiles and writes one report per profile; a boot imports the app's WSGI or ASGI module (`../../python/django_boot.py`), whose handler runs the boot check. `suite/suite-refusals.ts` lists the cases the consumer does not run, with the reason: none, it runs every case.
