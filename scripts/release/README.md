Release scripts of `release.yml`: the version stamp and its check, the npm packing with its content check, the idempotent publish to npm, the local registry of the rehearsal, and the check of the binaries against `SHA256SUMS`; `jvm/` holds the Maven Central and Gradle Plugin Portal side.

- `node scripts/release/stamp.ts <version>` writes the version into every `package.json` (dropping `private` from the published packages), `access: "public"` in `.changeset/config.json`, the `version` of each pack's `pack.yaml`, the runtime version constants (Node, Python, PHP), `jvm/gradle.properties`, every `python/*/pyproject.toml` (each requirement on another seampact distribution pinned `==<version>`) and `python/uv.lock`. Run it once on the release branch and commit the result.
- `node scripts/release/check-version.ts <version>` fails, naming each field, when the checkout is not at the version.
- `node scripts/release/run-version.ts <version> --mode real|dry-run` checks the version of a run; a real run refuses `0.0.0`.
- `node scripts/release/pack-npm.ts <version> --out <dir> --manifest <file>` builds and packs the published packages, then checks each tarball: only tracked files and build output, no test or fixture, `LICENSE` and `README.md` present, the manifest at the version with the repository npm provenance checks, the `@seampact/*` dependencies and a pack's `pack.yaml` at the version. It writes the name, version and SHA-256 of each tarball to the manifest file.
- `node scripts/release/publish-npm.ts <dir> --manifest <file> --version <version> --registry <url> [--provenance]` takes exactly the tarballs of the manifest, each checked against its hash and the packages of the release, publishes the versions the registry lacks, skips the ones it holds with the same bytes, and fails by name, before publishing anything, on one it holds with other bytes.
- `scripts/release/start-verdaccio.sh <work-dir>` starts the local registry of the rehearsal (`verdaccio.yaml`); `scripts/release/verify-assets.sh <dir> <sums-sha256>` checks the binaries before an upload; `node scripts/release/latest-release.ts <version>` says whether the release takes the latest mark.
- `python/` holds the PyPI scripts (distribution manifest, upload plan, local index) and `php/` the PHP mirror scripts (mirror commits, push, load check), each with its own README; `scripts/php-split.sh` splits the PHP packages.
