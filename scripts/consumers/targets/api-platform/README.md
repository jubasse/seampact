The API Platform consumer (ADR 0029 "The consumer and the proof"): the Symfony consumer's app, served through API Platform 5's routes instead of the route loaders, and run with the shared http suite under PHP's built-in server.

- `assemble.sh <work> <bundled> <7.4|8>` assembles the Symfony consumer in `<work>/app` (`../symfony/assemble.sh`), then `derive.php` turns it into the API Platform one: `Kernel.php` registers `ApiPlatformBundle`, maps the generated resources and imports API Platform's routes in place of the route loaders, `seampact.config.yaml` uses `seampact/api-platform`, and `composer.json` adds API Platform 5 and the path repository of `php/api-platform`. Each edit must apply, or the Symfony consumer changed under it.
- In the app: `composer update`, `../symfony/check-majors.sh <app> <7.4|8>`, `vendor/bin/seampact generate`, then `php bin/console cache:warmup`, which runs the boot check.
- From the repository root, with `SEAMPACT_API_PLATFORM_APP` and `SEAMPACT_API_PLATFORM_REPORTS` set: `pnpm vitest run --config scripts/consumers/targets/api-platform/suite/vitest.config.ts` serves the app and runs the `default` and `hand-written` profiles and the `boot` profile (each case warms the app of its variant with `cache:warmup`: `assemble.sh ... allow-listed|route-check-off|hook-check-off` builds the variant apps, whose env variables are `SEAMPACT_API_PLATFORM_ALLOW_LISTED_APP`, `..._ROUTE_CHECK_OFF_APP` and `..._HOOK_CHECK_OFF_APP`), and with `SEAMPACT_API_PLATFORM_PACK_APP` the `pack:api-platform` profile (`suite/pack.suite.ts`). `suite/suite-refusals.ts` lists the cases the app does not run, with the reason: the changes feed and the input-rules case. `suite/native-security.suite.ts` proves API Platform's `security` after the boundary, with `src/SecurityProbeMetadata.php`, which `derive.php` copies into the app.

- `assemble.sh <work> <bundled> <7.4|8> pack-api-platform` builds the pack app: `<bundled>` is the bundle of `fixtures/golden/pack-api-platform/contract` (`../php/bundle.sh <binary> <out> fixtures/golden/pack-api-platform/contract`), the Symfony consumer's `pack-laravel` variant (its handlers answer the page items and total) is assembled over it into `<work>/app-pack-laravel`, and `derive.php` turns it into the API Platform one. The profile reads the default cases through the pack's JSON-LD format, its Hydra paging and its 422 violations body, then runs the pack's own cases (item and member `@id`, violations).
