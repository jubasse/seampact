Test consumers of the packed packages: build, pack, assemble a consumer from the template and a target overlay after its chain of base overlays (each `overlay.base` lists its bases one per line, each base's own chain first, of any depth, never a cycle), then install, generate, check (clean, then after a hand edit of a generated file, which must name that file), typecheck and test it (scripts/consumers). Consumer sources use `.mts` so the monorepo's own typecheck and test globs leave them to the consumer, where they are checked. `--validators <id>` (default `zod`) picks the validator library a consumer generates with, from `validator-choice.ts`. The test step runs the `default`, `hand-written` and `boot` profiles of `@seampact/http-suite` and writes one report per profile, keyed by checklist id and naming the target (`.seampact-target`), to `reports/http-suite-<profile>.json` in the consumer. The HTTP profiles run against the server the overlay starts; each boot case starts `test/boot-entry.mts` under `tsx` in a process of its own with a misconfigured variant (`src/boot-variant.mts`), which the template's hooks and each overlay's handler registration apply. Each overlay serves the suite's control routes beside the contract routes, from the template's `src/suite-control.mts`; the template's hooks and handlers answer from the script a case loads and record each authenticate and decide call. The `front` overlay adds a Vitest browser project on Playwright Chromium, whose headless shell the run installs; when the base overlay provides `test/server.mts`, its config starts that server, proxies the apis' base paths and the control routes to it from the page's origin, and provides its URL and credentials to `test/front/*.browser.test.*`; `front-fetch` (on `hono` and `front`) drives the generated fetch client there. The `react` overlay (on `front`) adds React, Vite and the stricter tsconfig of a default Vite React TypeScript app, and builds the app for production; `react-tanstack` (on `hono` and `react`) generates TanStack Query options and hooks over the fetch client and drives them in the browser against the Hono server.
