Test consumers of the packed packages: build, pack, assemble a consumer from the template and a target overlay after its chain of base overlays (each `overlay.base` lists its bases one per line, each base's own chain first, of any depth, never a cycle), then install, generate, check (clean, then after a hand edit of a generated file, which must name that file), typecheck and test it (scripts/consumers). Consumer sources use `.mts` so the monorepo's own typecheck and test globs leave them to the consumer, where they are checked. `--validators <id>` (default `zod`) picks the validator library a consumer generates with, from `validator-choice.ts`. The test step runs the `default`, `hand-written` and `boot` profiles of `@seampact/http-suite` and writes one report per profile, keyed by checklist id and naming the target (`.seampact-target`), to `reports/http-suite-<profile>.json` in the consumer. The HTTP profiles run against the server the overlay starts; each boot case starts `test/boot-entry.mts` under `tsx` in a process of its own with a misconfigured variant (`src/boot-variant.mts`), which the template's hooks and each overlay's handler registration apply. Each overlay serves the suite's control routes beside the contract routes, from the template's `src/suite-control.mts`; the template's hooks and handlers answer from the script a case loads and record each authenticate and decide call. The `front` overlay adds a Vitest browser project on Playwright Chromium, whose headless shell the run installs; when the base overlay provides `test/server.mts`, its config starts that server, proxies the apis' base paths and the control routes to it from the page's origin, and provides its URL and credentials to `test/front/*.browser.test.*`; `front-fetch` (on `hono` and `front`) drives the generated fetch client there. The `vite` overlay (on `front`) adds Vite and builds the consumer's app for production. The `react` overlay (on `vite`) adds React and the stricter tsconfig of a default Vite React TypeScript app; `react-tanstack` (on `hono` and `react`) generates TanStack Query options and hooks over the fetch client and drives them in the browser against the Hono server. `react-swr` and `react-rtk` (each on `hono` and `react`) do the same with SWR hooks and the RTK Query api; the compatibility matrix tests React 19 on `react-tanstack`, and `@tanstack/react-query` 5, `swr` 2 and `@reduxjs/toolkit` 2 with `react-redux` 9 on their own overlays. The `vue` overlay (on `vite`) adds Vue 3 and `vitest-browser-vue`; `vue-tanstack`, `vue-pinia-colada` and `vue-fetch` (each on `hono` and `vue`) generate Vue Query, Pinia Colada and plain fetch composables over the fetch client and drive them in the browser against the Hono server. The `angular` overlay (on `vite`) adds Angular 22, compiled in the page by its JIT compiler with no build step; `angular-fetch` (on `hono` and `angular`) generates the Angular api service over the fetch client, sending through `HttpClient`, and drives its readers and mutations in the browser against the Hono server. `angular-ngrx` (on `hono` and `angular`) generates the NgRx action groups and effects over that service and dispatches them through the app's own store and reducer. `angular-ngrx-signals` (on `hono` and `angular`) generates the Signal Store features over that service and composes them into the app's own `signalStore`.
