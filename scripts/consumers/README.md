Test consumers of the packed packages: build, pack, assemble a consumer from the template and a target overlay after its chain of base overlays (each `overlay.base` lists its bases one per line, each base's own chain first, of any depth, never a cycle), then install, generate, check (clean, then after a hand edit of a generated file, which must name that file), typecheck and test it (scripts/consumers). Consumer sources use `.mts` so the monorepo's own typecheck and test globs leave them to the consumer, where they are checked. `--validators <id>` (default `zod`) picks the validator library a consumer generates with, from `validator-choice.ts`. `--pack <name>` builds a server consumer from the reference contract with `@seampact/pack-<name>` applied (its golden case, `fixtures/golden/pack-<name>/`), copies the `pack/` overlay last and runs that pack's suite profile in place of the target's own profiles, reporting to `reports/http-suite-pack-<name>.json`. The test step runs the `default`, `hand-written` and `boot` profiles of `@seampact/http-suite` and writes one report per profile, keyed by checklist id and naming the target (`.seampact-target`), to `reports/http-suite-<profile>.json` in the consumer. The HTTP profiles run against the server the overlay starts; each boot case starts `test/boot-entry.mts` under `tsx` in a process of its own with a misconfigured variant (`src/boot-variant.mts`), which the template's hooks and each overlay's handler registration apply. Each overlay serves the suite's control routes beside the contract routes, from the template's `src/suite-control.mts`; the template's hooks and handlers answer from the script a case loads and record each authenticate and decide call. The `front` overlay adds a Vitest browser project on Playwright Chromium, whose headless shell the run installs; when the base overlay provides `test/server.mts`, its config starts that server, proxies the apis' base paths and the control routes to it from the page's origin, and provides its URL and credentials to `test/front/*.browser.test.*`; `front-fetch` (on `hono` and `front`) drives the generated fetch client there. The `vite` overlay (on `front`) adds Vite and builds the consumer's app for production. The `react` overlay (on `vite`) adds React and the stricter tsconfig of a default Vite React TypeScript app; `react-tanstack` (on `hono` and `react`) generates TanStack Query options and hooks over the fetch client and drives them in the browser against the Hono server. `react-swr` and `react-rtk` (each on `hono` and `react`) do the same with SWR hooks and the RTK Query api; the compatibility matrix tests React 19 on `react-tanstack`, and `@tanstack/react-query` 5, `swr` 2 and `@reduxjs/toolkit` 2 with `react-redux` 9 on their own overlays. The `vue` overlay (on `vite`) adds Vue 3 and `vitest-browser-vue`; `vue-tanstack`, `vue-pinia-colada` and `vue-fetch` (each on `hono` and `vue`) generate Vue Query, Pinia Colada and plain fetch composables over the fetch client and drive them in the browser against the Hono server. The `angular` overlay (on `vite`) adds Angular 22, compiled in the page by its JIT compiler with no build step; `angular-fetch` (on `hono` and `angular`) generates the Angular api service over the fetch client, sending through `HttpClient`, and drives its readers and mutations in the browser against the Hono server. `angular-ngrx` (on `hono` and `angular`) generates the NgRx action groups and effects over that service and dispatches them through the app's own store and reducer. `front-msw` (on `front` alone) generates MSW handlers and runs the fetch client against them with no server, in its own node project under `setupServer` and in the browser project under `setupWorker`, with its own Vitest config and tsconfig that leave out the template's server tests. `angular-ngrx-signals` (on `hono` and `angular`) generates the Signal Store features over that service and composes them into the app's own `signalStore`. The Spring Boot, Laravel, Symfony and FastAPI consumers are built by their own scripts (`targets/spring-boot/README.md`, `targets/laravel/README.md`, `targets/symfony/README.md`, `targets/fastapi/README.md`); `served-app.ts` starts their server process on a free port for their suite. The Python consumers share `python/` (`python/README.md`): the hash-pinned install from built wheels, the uvicorn and gunicorn launchers, the boot runner and the suite doubles behind the control routes.

## A Python test consumer outside the repository

The recipe for a fresh FastAPI project in `~/Dev/test-seampact-fastapi` (ADR 0011 "Unpublished installs for test consumers"), as a user installs it. Build the binary once (`pnpm build` in `packages/tools/binary`); the other steps need no Node.

```sh
repo=~/Dev/seampact
work=~/Dev/test-seampact-fastapi
mkdir -p "$work" && cd "$work"

# One wheel per package, then the third-party requirements pinned by hash from the lock file.
"$repo/scripts/consumers/python/build-wheels.sh" "$work/wheels"
"$repo/scripts/consumers/python/requirements.sh" requirements.txt seampact-fastapi generate uvicorn

# A new virtual environment: the requirements from PyPI by hash, then the seampact wheels with no index.
"$repo/scripts/consumers/python/install.sh" venv requirements.txt wheels 'seampact-fastapi[generate]'
git -C "$repo" rev-parse HEAD > .seampact-commit

# Generate from the reference contract's local YAML (the binary is pinned by path and hash) and check it.
"$repo/scripts/consumers/python/local-yaml.sh" projects venv "$repo/packages/tools/binary/dist/bin/seampact-linux-x64" seampact-fastapi
```

`projects/fastapi` is the generated project (`seampact.config.yaml`, `pyproject.toml` with `[tool.seampact.binary]`, `generated/`, `openapi/`). To serve a full app, `targets/fastapi/assemble.sh` builds the sample app from a bundle (`targets/fastapi/README.md`); DRF takes the same steps with `seampact-drf` and `targets/drf`. To run the channel smoke by hand, start `scripts/dist-smoke/cli.ts serve --work <dir>` and run `scripts/consumers/python/channel-smoke.sh <new dir> venv <its JSON line saved to a file> seampact-fastapi`.
