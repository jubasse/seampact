The Django Ninja consumer (ADR 0027 "The consumer and the proof"): a Django project that `seampact-ninja` generates the reference contract's tasks api into, serving every operation of the `tasks` and `tasksService` apis on one `NinjaAPI`, and the suite run that checks it with the shared http suite under gunicorn (WSGI, sync views) or uvicorn (ASGI, async views).

- `../../php/bundle.sh <binary> <out>` bundles the reference contract with the compiler binary into `<out>/bundle` and writes its integrity pin to `<out>/integrity`; it is the one step that needs the binary.
- `SEAMPACT_NINJA_VIEWS=<sync or async> assemble.sh <work> <out> [allow-listed]` assembles the app as the shared `../../python/assemble.sh` does, with the views it names in both entries' options: `<work>/app`, or `<work>/app-allow-listed` built from `seampact.allow-listed.config.yaml` for the `allow-listed-framework-route` boot variant. It copies in the FastAPI consumer's `handlers.py` and `sample_data.py` (the same Pydantic operations), the DRF consumer's Django control views and the shared `../../python/reference_doubles/hook_doubles.py`.
- The install (`../../python/README.md`): `requirements.sh <file> seampact-ninja generate <gunicorn or uvicorn>` and `scripts/consumers/python/build-wheels.sh <wheels>`, then `install.sh <venv> <file> <wheels> 'seampact-ninja[generate]' [python/ninja/ci/floor-requirements.txt]`; in an assembled app, `<venv>/bin/seampact generate`.
- `app/settings.py` lists the generated boundary of each api first in `MIDDLEWARE` and holds no `SEAMPACT` entry; `app/api.py` builds the `NinjaAPI`, whose app-wide `auth=` would refuse every request, and binds every api with the handler factories of `app/handler_factories.py`, the hook factories of `app/hooks.py` and, for the `identity` access kind, the bearer authentication of `app/auth.py`, whose caller the `user` hook reads; less what `SEAMPACT_SUITE_BOOT_VARIANT` leaves out. `app/urls.py` includes `api.urls` beside the control views; `app/wsgi.py` and `app/asgi.py` are the served apps.
- From the repository root, with `SEAMPACT_NINJA_SERVER` (`gunicorn` or `uvicorn`), `SEAMPACT_NINJA_APP`, `SEAMPACT_NINJA_ALLOW_LISTED_APP`, `SEAMPACT_NINJA_VENV` and `SEAMPACT_NINJA_REPORTS` set: `pnpm vitest run --config scripts/consumers/targets/ninja/suite/vitest.config.ts` runs the `default`, `hand-written` and `boot` profiles and writes one report per profile; a boot imports the app's WSGI or ASGI module (`../../python/django_boot.py`). `suite/suite-refusals.ts` lists the cases the consumer does not run: none.
