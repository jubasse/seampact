The Laravel consumer (ADR 0023 "The consumer and the proof"): a Laravel 13 app that `seampact/laravel` generates every operation of the reference contract's apis into, its controllers, hook doubles and control routes, and the suite run that checks it with the shared http suite under PHP's built-in server.

- `../../php/bundle.sh <binary> <out>` bundles the reference contract with the compiler binary into `<out>/bundle` and writes its integrity pin to `<out>/integrity`; it is the one step that needs the binary.
- `assemble.sh <work> <out> [allow-listed|route-check-off|hook-check-off|pack-laravel]` copies the app into `<work>/app` (`allow-listed`: `<work>/app-allow-listed`, built from `seampact.allow-listed.config.yaml` for the `allow-listed-framework-route` boot variant; `route-check-off` and `hook-check-off` build the apps of the boot variants that switch the framework-route check off and the hook check off (`seampact.<variant>.config.yaml`; the second filters `health` out and goes without its handler), into `<work>/app-<variant>`; `pack-laravel`: `<work>/app-pack-laravel`, whose `pack-laravel/app` paged lists answer Laravel's `LengthAwarePaginator`, from the bundle of `fixtures/golden/pack-laravel/contract` that `../../php/bundle.sh <binary> <out> fixtures/golden/pack-laravel/contract` writes), points its path repositories at the repository's `php/` packages, commits the bundle into the local git repository `<work>/contract-repo` tagged `v1.0.0` and points the app config at it with the integrity pin (`../spring-boot/contract-source.sh`).
- The `input-rules` case's api, `inputRules`, is a second source: `packages/tools/http-suite/contracts/input-rules` bundled by `../../php/bundle.sh <binary> <work>/bundles/input-rules packages/tools/http-suite/contracts/input-rules`, which `assemble.sh` reads from the `input-rules` directory beside the reference bundle and commits into `<work>/contract-repo-input-rules`. `app/Suite/Rules` holds its three rules.
- In an assembled app: `composer update`, `vendor/bin/seampact generate`, then `php artisan route:cache` and `php artisan config:cache`. No lock is committed: `laravel/framework` is held to 13.38 patches and the rest resolves for the PHP 8.3.36 platform.
- `config/seampact/tasks.php` puts `app/Http/Middleware/NativeLayers.php` on the tasks api's identity routes only (`middleware.identity`): an `X-Suite-Native-Layer` header makes it run Laravel's `auth:sanctum` middleware or `abort(401|403|429)`. `laravel/sanctum` is installed, so its CSRF cookie route serves beside the contract routes; the suite provider gives the app an array session driver and a fixed test key.
- `config/seampact/tasksAbsoluteUrls.php` gives the tasksAbsoluteUrls api its public origin, `https://api.seampact.test`, which its absolute page links start with whatever Host the request names.
- The hook doubles keep the loaded script, the recorded hook calls and the log lines in `storage/suite-control.json`, since each request of PHP's built-in server starts from nothing. `SEAMPACT_SUITE_BOOT_VARIANT` leaves out the binding its variant names.
- From the repository root, with `SEAMPACT_LARAVEL_APP`, `SEAMPACT_LARAVEL_ALLOW_LISTED_APP`, `SEAMPACT_LARAVEL_ROUTE_CHECK_OFF_APP`, `SEAMPACT_LARAVEL_HOOK_CHECK_OFF_APP`, `SEAMPACT_LARAVEL_PACK_APP` and `SEAMPACT_LARAVEL_REPORTS` set: `pnpm vitest run --config scripts/consumers/targets/laravel/suite/vitest.config.ts` serves the app with `php -S` and runs the `default`, `hand-written`, `boot` and `pack:laravel` profiles, and writes one report per profile; a boot runs `php artisan route:cache`, which runs the boot check. `suite/suite-refusals.ts` lists the cases the consumer does not run, with the reason.
