The registry proof of a release: one consumer per family installs the released artefacts from a registry, the rehearsal's local ones in `release.yml` or the real ones in `post-release.yml`, generates the reference contract and passes the http suite's `default` profile.

- `node scripts/release/registry-proof/node-consumer.ts --registry <url> --version <version> --dir <new-dir>` assembles the NestJS consumer of `scripts/consumers` with every published `@seampact/*` package at the version from the registry, then installs, generates, checks, typechecks and runs its `default`, `hand-written` and `boot` profiles.
- `scripts/release/registry-proof/spring-boot.sh <gradle|maven> <file-repository>|registries <version> <work-dir> [<compiler-binary>]` builds the Spring Boot consumer with the Gradle or the Maven plugin from the rehearsal's file repository alone, or from Maven Central and the Gradle Plugin Portal, into `<work-dir>/gradle/build/libs/consumer.jar` or `<work-dir>/maven/target/consumer.jar`. With the file repository the compiler is the given release binary, pinned by path; with `registries` the consumer pins nothing and the plugin resolves the compiler artefact of its own pin from Maven Central.
- `scripts/release/registry-proof/laravel.sh <bundled> <version> <work> [<bare-mirrors-dir>]` assembles the Laravel consumer into `<work>/app` with the `seampact/*` packages at the version from the bare mirrors, or from Packagist, through `composer-registry.ts`, then generates and caches it. `<bundled>` is what `scripts/consumers/php/bundle.sh` wrote.
- `scripts/release/registry-proof/fastapi.sh <bundled> <version> <work> [<local-index-url>]` installs `seampact-fastapi[generate]`, `seampact-signed-webhooks` and `seampact-ir[compiler]` at the version into `<work>/venv` from the local simple index first, or from PyPI, then assembles and generates the FastAPI consumer into `<work>/app`; its OpenAPI document is written by the binary of the `seampact-compiler` wheel.
- From the repository root, with `SEAMPACT_PROOF_TARGET` (`spring-boot`, `laravel` or `fastapi`), `SEAMPACT_PROOF_APP` (the jar or the app directory), `SEAMPACT_PROOF_VENV` (FastAPI) and `SEAMPACT_PROOF_REPORTS` set: `pnpm vitest run --config scripts/release/registry-proof/vitest.config.ts` serves the consumer and runs the `default` profile, writing its report.
