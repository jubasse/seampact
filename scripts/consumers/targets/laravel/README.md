The Laravel consumer (ADR 0023 "The consumer and the proof"): a Laravel 13 app that `seampact/laravel` generates the core operations of the reference contract's tasks api into, its controllers, hook doubles and control routes, and the suite run that checks it with the shared http suite under PHP's built-in server.

- `bundle.sh <binary> <out>` bundles the reference contract with the compiler binary into `<out>/bundle` and writes its integrity pin to `<out>/integrity`; it is the one step that needs the binary.
- `assemble.sh <work> <out> [allow-listed]` copies the app into `<work>/app` (`allow-listed`: `<work>/app-allow-listed`, built from `seampact.allow-listed.config.yaml` for the `allow-listed-framework-route` boot variant), points its path repositories at the repository's `php/` packages, commits the bundle into the local git repository `<work>/contract-repo` tagged `v1.0.0` and points the app config at it with the integrity pin (`../spring-boot/contract-source.sh`).
- In an assembled app: `composer update`, `vendor/bin/seampact generate`, then `php artisan route:cache` and `php artisan config:cache`. No lock is committed: `laravel/framework` is held to 13.38 patches and the rest resolves for the PHP 8.3.36 platform.
- The hook doubles keep the loaded script, the recorded hook calls and the log lines in `storage/suite-control.json`, since each request of PHP's built-in server starts from nothing. `SEAMPACT_SUITE_BOOT_VARIANT` leaves out the binding its variant names.
- From the repository root, with `SEAMPACT_LARAVEL_APP`, `SEAMPACT_LARAVEL_ALLOW_LISTED_APP` and `SEAMPACT_LARAVEL_REPORTS` set: `pnpm vitest run --config scripts/consumers/targets/laravel/suite/vitest.config.ts` serves the app with `php -S` and runs the `default`, `hand-written` and `boot` profiles, and writes one report per profile; a boot runs `php artisan route:cache`, which runs the boot check. `suite/suite-refusals.ts` lists the cases that wait for a later PR, with the reason.
