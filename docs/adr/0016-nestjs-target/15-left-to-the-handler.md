### Left to the handler

Some forms of the reference contract are validated or passed on by the boundary but enforced by the handler (ADR 0012 "Errors the handler answers"). `generate` names each with a warning, not a refusal, carrying the operation, the IR member and what the handler does, and the CLI prints it on stderr: `concurrency` (`concurrency.handler`: the handler compares the version and answers the `stateConflict` code), `owner: caller` (`owner.handler`: the handler scopes its reads and writes to the principal), the deadline header and `budgetMs` (`deadline.handler`), sort keys (`paging.sortKeys.handler`: the boundary validates the key, the handler orders by it) and an identity's request-side `headers` (`identity.headers.handler`: validated as declared headers only). An identity header written on a response (a `versionToken` header, or one declared `in: response`) is no warning: no handler can write it, so `generate` refuses it by name (`identity.response.header.unsupported`). `filteredBy` carries no warning: grammar section 10 makes the list filter the application's own by design, reaching only the handler context and the documents.
