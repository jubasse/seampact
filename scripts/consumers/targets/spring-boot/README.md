The Spring Boot consumer (ADR 0022 "The consumer and the proof"): a Spring Boot 4 app built by the Gradle or the Maven plugin from the reference contract, as YAML or as a bundle served over HTTPS, its controllers, hook doubles and control routes, and the suite run that checks it with the shared http suite.

- `assemble.sh <dir> [allow-listed|pack-spring] [gradle|maven]` copies the app, its build root (Gradle by default, with the repository's Gradle wrapper, or Maven with `mvnw`) and the reference contract into `<dir>`; `allow-listed` takes the config of the `allow-listed-framework-route` boot variant; `pack-spring` takes the contract with `@seampact/pack-spring` applied, `pack-spring/src` (its paged lists answer Spring Data's `Page`) and Spring Data Commons.
- In a Gradle `<dir>`: `./gradlew test bootJar -PseampactJvm=<repo>/jvm -PseampactBinary=<binary> [-PjavaVersion=25]` runs `GeneratedRedactionTest` and builds `build/libs/consumer.jar`; the plugin and `seampact-hooks` come from the repository's `jvm/` build, included by path.
- In a Maven `<dir>`: `./mvnw package -DseampactBinary=<binary> -DseampactBinarySha256=<sha256> [-Djava.version=25]` runs the same tests and builds `target/consumer.jar`; the plugin and `seampact-hooks` come from Maven local (`./gradlew publishToMavenLocal` of `seampact-ir`, `seampact-hooks`, `seampact-spring-boot`, `seampact-runner` and `seampact-maven-plugin` in `jvm/`).
- `bundle-over-https.sh start <work>` serves `<work>/bundles` over HTTPS on port 8443 with `serve/Serve.java` and a loopback certificate; `bundle-over-https.sh use <work> <dir> <binary> <name>` bundles the app's contract, points its config at the served tarball with the integrity pin and removes the YAML sources. The build trusts the server through `JAVA_TOOL_OPTIONS=-Djavax.net.ssl.trustStore=<work>/truststore.p12 -Djavax.net.ssl.trustStorePassword=changeit`.
- From the repository root, with `SEAMPACT_SPRING_JAR`, `SEAMPACT_SPRING_ALLOW_LISTED_JAR`, `SEAMPACT_SPRING_PACK_JAR` and `SEAMPACT_SPRING_REPORTS` set: `pnpm vitest run --config scripts/consumers/targets/spring-boot/suite/vitest.config.ts` runs the `default`, `hand-written`, `boot` and `pack:spring` profiles and a forwarded-prefix check, and writes one report per profile. `suite/suite-refusals.ts` lists the cases a profile does not run, with the reason.
