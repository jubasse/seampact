### Registration

Each api gets one dynamic module (`SeampactModule.forRoot({ authenticate, deciders, scopeResolvers, idempotencyStore, onUnexpectedError }, { logger })`, or `SeampactModule.forRootAsync({ imports, inject, useFactory }, { logger })` for hooks built from the app's providers, in the shape of NestJS's `ConfigurableModuleBuilder`); `onUnexpectedError` and the options are optional. The options are `logger`, `responses`, `bodyValidation` and `unboundOperations`. `logger` takes the boundary's warnings and unexpected failures, as the other Node targets' registration option does; without it the boundary writes through NestJS's `Logger` with the context `Seampact:<api>`, so `app.useLogger(...)` and its levels apply (the other Node targets keep the console). `responses` and `bodyValidation` default to the generated target option, a value of the wrong kind is a boot problem naming the option, and a `responses()` decorator on a controller or a method still wins over the module's mode. `unboundOperations` is `error` (the default: the boot check refuses an operation no controller method binds) or `warn`, which logs the unbound operations once and lets a test module hold some controllers; any other value is a boot problem, and a request to an unbound operation's route answers the api's `notFound` 404 in its format, not a 500. `forRootAsync` registers the factory under the exported `SEAMPACT_HOOKS`, and the module resolves the hooks from that token, so `overrideProvider(SEAMPACT_HOOKS)` replaces them in a test before the boot check reads them. Hooks are NestJS providers registered under explicit injection tokens, the api's exported `SEAMPACT_HOOKS` holding the app's hooks, so a test replaces them with `overrideProvider`: an authenticate hook per identity, or one serving several; a decider by a list of right and rule names, or all; a scope resolver per scope kind, or one serving several. Two deciders claiming one name is a boot error, and no default hook exists (ADR 0012 "Registration and per-right overrides"). Names that ADR 0007 has no role for are fixed words, without the api's segments: PascalCase for classes (`SeampactModule`), camelCase for decorators, functions and values (`responses`, `preRoutingFilter`, `keepRawBody`, `renderPreRoutingError`) and upper snake case for constants (`LARGEST_BODY_LIMIT`); the per-operation decorators follow "Placement". Each api's copy is its own module, so two apis in one app never collide once imported as namespaces (ADR 0007 section 7). The api-neutral exports behave the same in every api's copy: `renderContractError` and `isContractRoute` read the api from the boundary's request context or the route metadata, and `MAX_CHECKED_ERROR_BODY_BYTES` and `MAX_RENDERED_ISSUES` are fixed values. Each api's boot check covers its own operations, and refuses a second registration of the api in one app by name (here a second `forRoot` of one api), since replies written outside a request context report to one registration's hooks; the Fastify and AdonisJS targets refuse it too.
