### Errors raised before routing

These reach only the global filters: a body the platform's JSON parser cannot parse (400), a body above the app-wide parser limit (413), a path no route serves (404). The target exports, per api, a global filter instance and a helper for them (`preRoutingFilter`, `renderPreRoutingError(exception, host)`). They act only when the boundary's request context is absent, since the module middleware opens it on every contract route before any handler-side exception can be thrown; then, on a request that matches a contract route's path template, they render the refusal in that api's format. On any other request, the filter hands the exception to NestJS's default `BaseExceptionFilter` and the helper returns that it did nothing. NestJS tries the last registered global filter first and gives the exception to that one alone, so the exported filter matches no exception raised on a contract route, which the app's filters keep, and suits for the others an app without a global filter of its own; an app with one, or with two apis, calls each api's helper first in its own global filter. Without either, NestJS's default JSON body answers these refusals on contract routes, with the right status and the wrong format; the README's NestJS setup shows both forms. For two apis, one `@Catch()` filter extending `BaseExceptionFilter`, built with `app.getHttpAdapter()`, tries each api's `renderPreRoutingError(exception, host)` in turn and calls `super.catch(exception, host)` when none acts. A method the path does not serve (`PUT` on a task) is a 404 NestJS raises before routing, so the filter answers it with that path's `notFound` code: the contract has no 405. On every Node target, a method a contract path does not serve (`OPTIONS` included) on a path whose operations declare no 404 answers a bare 404 with no body; nothing failed, so `onUnexpectedError` is not called. A request whose raw path is under one of the api's base paths (its surfaces' resolved prefixes, case-sensitive, after the mount) and that no contract route serves exactly (a trailing slash, `//`, a percent-encoded static segment, an unknown sub-path) answers the api's `notFound` code (404) in its format on every Node target, never a domain 404 code of one operation, and bare when no operation carries the `notFound` role; a path outside the base paths (`/V1/...` on `/v1`) is the app's. Two apis of one app may share a base path (the default `/v{version}` prefix gives every version-1 api `/v1`): each api records its base paths in a per-app registry when it is registered, and a path under a base path that another api of the app also claims is left to the app (Express `next()`, Fastify `reply.callNotFound()`, NestJS and AdonisJS their default 404), so no api answers another's routes. The Express router reads the contract routers mounted on the app from the app's router stack at request time, so the mount order does not matter. `HEAD` on a path with a `GET` operation runs that operation fully (access, validation, no idempotency) and writes its status and headers without a body (RFC 9110 section 9.3.2), on every Node target. The filter delegates to `BaseExceptionFilter` with the HTTP adapter the api's module records when it starts, so the app's own routes keep NestJS's statuses and its error log; an unclaimed exception on a contract route is also kept for `onUnexpectedError` when the reply NestJS writes for it violates the contract. A pre-routing 500 (a parser limit below a route's limit) calls `onUnexpectedError` too.
