The JVM side of `release.yml`: staging and signing the Maven Central and Gradle Plugin Portal bundles, their local check and manifest, the idempotent Central publish, the local Central Portal of the rehearsal, and the rehearsal's consumers.

- `scripts/release/jvm/stage.sh <assets-dir> <out-dir>` stages `<out-dir>/central` (every module but the Gradle plugin, the compiler's binaries checked against `SHA256SUMS`) and `<out-dir>/plugin-portal` (the plugin and its marker, after `validatePlugins`), signed with the key of `ORG_GRADLE_PROJECT_seampactSigningKey`, at the stamped version of `jvm/gradle.properties`.
- `node scripts/release/jvm/bundle.ts check <dir> --channel central|plugin-portal --version <version> --key <file> [--sums <SHA256SUMS>] --manifest <out-file>` checks a staged bundle as Central does (coordinates, POM fields, sources and javadoc jars, MD5 and SHA-1, signatures, compiler hashes), then writes its manifest; `bundle.ts verify <dir> --manifest <file>` checks a downloaded bundle against it.
- `node scripts/release/jvm/publish-central.ts <dir> --manifest <file> --version <version> [--portal <url>] [--repository <url>]` uploads the versions Central lacks as `USER_MANAGED`, publishes them once `VALIDATED`, skips the ones it holds with the same bytes and fails by name on other bytes; the token comes from `MAVEN_CENTRAL_USERNAME` and `MAVEN_CENTRAL_PASSWORD`.
- `node scripts/release/jvm/local-portal.ts <repository-dir> --url-file <file>` serves the publisher API on the loopback for the rehearsal and publishes into a file repository.
- `scripts/release/jvm/build-plugin.sh <assets-dir> [task...]` rebuilds the Gradle plugin's published files; `node scripts/release/jvm/plugin-portal-plan.ts --manifest <file> --version <version>` checks them against the manifest and prints `publish=true` when the portal lacks the version.
- `scripts/release/jvm/rehearse-consumers.sh <file-repository> <version> <binary> <work-dir>` builds the Spring Boot consumer with the Gradle and the Maven plugin from the file repository.
