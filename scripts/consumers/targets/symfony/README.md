The Symfony consumer (ADR 0024 "The consumer and the proof"): a Symfony 7.4 or 8 app that `seampact/symfony` generates the core operations of the reference contract's tasks api into, its controllers, hook doubles, security layers and control routes, and the suite run that checks it with the shared http suite under PHP's built-in server.

- `../../php/bundle.sh <binary> <out>` bundles the reference contract with the compiler binary, as for the Laravel consumer.
- `assemble.sh <work> <out> <7.4|8> [allow-listed]` copies the app into `<work>/app` (`allow-listed`: `<work>/app-allow-listed`, built from `seampact.allow-listed.config.yaml` for the `allow-listed-framework-route` boot variant), holds every Symfony package to the major (8 moves the platform to PHP 8.5.12), points its path repositories at the repository's `php/` packages, commits the bundle into the local git repository `<work>/contract-repo` tagged `v1.0.0` and points the app config at it with the integrity pin (`../spring-boot/contract-source.sh`).
- In an assembled app: `composer update`, `check-majors.sh <app> <7.4|8>` (every Symfony package on the row's major, transitive ones included), `vendor/bin/seampact generate`, then `php bin/console cache:warmup`, which runs the boot check. No lock is committed.
- `src/Kernel.php` registers FrameworkBundle, SecurityBundle (a lazy `http_basic` firewall on `^/v1` with one in-memory user, and an `access_control` rule matching the `x-seampact-suite-forbidden` header) and the api's bundle. `SEAMPACT_SUITE_BOOT_VARIANT` leaves out the service its variant names and gets its own cache directory; `SEAMPACT_SUITE_RESPONSES` sets the api's `responses` mode at run time and `SEAMPACT_SUITE_APP_DEBUG=true` boots the kernel in debug.
- The hook doubles keep the loaded script, the recorded hook calls and the log lines in `var/suite-control.json`, since each request of PHP's built-in server starts from nothing.
- From the repository root, with `SEAMPACT_SYMFONY_APP`, `SEAMPACT_SYMFONY_ALLOW_LISTED_APP` and `SEAMPACT_SYMFONY_REPORTS` set: `pnpm vitest run --config scripts/consumers/targets/symfony/suite/vitest.config.ts` serves the app with `php -S`, runs the `default`, `hand-written` and `boot` profiles and the Symfony edges, and writes one report per profile; a boot runs `php bin/console cache:warmup` into a cache directory of its own. `suite/suite-refusals.ts` lists the cases that wait for a later PR, with the reason.
